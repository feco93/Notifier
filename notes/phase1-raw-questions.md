## A. Events and "something important"
- Q01 What counts as an "event"?
- Q02 Who decides what is "important": the system, the user, or an admin?
- Q03 Is there one global importance threshold, or a per-user one?
- Q04 Which categories are in scope (news, markets, disasters, others)?
- Q05 How is severity measured per category?
- Q06 Should the same real-world event reported by several sources be merged?
- Q07 What latency is expected: seconds, minutes, hourly?
- Q08 Should we use ML/LLM classification to judge news importance?
- Q09 Which languages/locales of news?
- Q10 Should users be able to filter by geography?

## B. Data sources
- Q11 Which data providers?
- Q12 Are paid APIs / API keys acceptable?
- Q13 Push (webhooks/streams) or poll?
- Q14 Licensing / ToS of redistributing news content?
- Q15 What happens when a source is down?
- Q16 Backfill historical events on startup?

## C. Alerts
- Q17 What is an "alert": a saved rule, or a notification instance?
- Q18 How expressive are rules (AND/OR, keywords, thresholds)?
- Q19 Can one alert deliver to multiple channels?
- Q20 Frequency control: immediate, digest, quiet hours?
- Q21 Max alerts per user?
- Q22 Can alerts be shared within a team?
- Q23 Can alerts be paused/snoozed?

## D. Channels
- Q24 Which email provider?
- Q25 Slack: incoming webhook, Slack app with OAuth, or bot DMs?
- Q26 Message format / templates per channel?
- Q27 Must destinations be verified (confirm email, test Slack message)?
- Q28 What does "add more channels later" mean: runtime plugins or code-level extension?
- Q29 Delivery guarantees and retries?

## E. Users and admin
- Q30 Who are the users: internal staff, B2B customers, or the public?
- Q31 What authentication?
- Q32 What does the admin view contain?
- Q33 Can admins edit other users' alerts?
- Q34 Is an audit log needed?

## F. Non-functional
- Q35 Scale: number of users, events per day?
- Q36 Deployment target?
- Q37 Privacy / GDPR, unsubscribe links?
- Q38 Observability: metrics, logs?
